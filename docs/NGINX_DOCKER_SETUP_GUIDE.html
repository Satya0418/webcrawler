Production Architecture & Engineering Guide

Setting Up Nginx Reverse Proxy & Docker Compose for Multi-Service Web Applications
Target Audience: Full-Stack Engineers, DevOps, System Architects
Version & Status: Production Standard 1.0 (Enterprise & AWS Ready)
Scope: Docker Compose, Nginx, SSL Termination, Port Shielding
Applicability: Vite, Next.js, FastAPI, Node.js, Microservices

1. Executive Summary & Core Concept

In modern production environments, client web browsers and mobile apps should never connect directly to application runtime engines (Node.js, Vite, FastAPI/Uvicorn, Gunicorn, Django, etc.). Instead, Nginx serves as the unified perimeter reverse proxy.

CORE VALUE PROPOSITION
Placing Nginx in front of Docker containers provides unified routing under a single domain (eliminating CORS errors), port shielding, centralized SSL/TLS termination, Gzip asset compression, and persistent WebSocket support.

Traffic Flow Architecture

  1. Public Ingress: Clients connect to Port 80, 443, or 8443 (via AWS Load Balancer).
  2. Inspection & Termination: Nginx terminates SSL, applies rate limits, and inspects request paths.
  3. Internal Routing: Nginx proxies requests across the isolated Docker bridge network to internal containers.
  4. Shielded Services: Application runtimes and databases remain strictly internal and unreachable from the internet.

2. The Port Shielding Rule (expose vs. ports)

A critical security rule when authoring docker-compose.yml:

Directive Network Scope Host Visibility Applicable Services
ports: Public & Host Interface Exposes port to 0.0.0.0 (public internet) Nginx Gateway Only (e.g. 80:80, 8443:443)
expose: Internal Docker Bridge Only Hidden from host; accessible ONLY by peer containers All App Backends, Vite Frontends, Databases
IMPORTANT SECURITY DIRECTIVE
Never use ports: on databases (PostgreSQL, MongoDB) or internal API services. Only Nginx opens host ports.

3. Production Docker Compose Template (docker-compose.yml)

services:
  # 1. Application Service (React, Vite, or Backend API)
  app-backend:
    build:
      context: .
      dockerfile: Dockerfile
    container_name: ${APP_CONTAINER_NAME:-app_backend}
    env_file:
      - .env
    expose:
      - "5173" # Internal port (e.g. 5173 for Vite, 8000 for FastAPI)
    networks:
      default:
        aliases:
          - app_backend
    restart: unless-stopped

  # 2. Database Service (Private to Docker Network)
  db:
    image: postgres:15-alpine
    container_name: app_postgres_db
    environment:
      POSTGRES_USER: ${POSTGRES_USER:-postgres}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-postgres}
      POSTGRES_DB: ${POSTGRES_DB:-production_db}
    expose:
      - "5432"
    volumes:
      - postgres_data:/var/lib/postgresql/data
    restart: unless-stopped

  # 3. Nginx Reverse Proxy Gateway
  nginx:
    image: nginx:alpine
    container_name: ${NGINX_CONTAINER_NAME:-app_nginx_gateway}
    depends_on:
      - app-backend
    ports:
      - "${HTTP_PORT:-80}:80"
      # For SSL / AWS ALB deployments:
      # - "${HTTPS_PORT:-8443}:443"
    volumes:
      - ./nginx/nginx.conf:/etc/nginx/nginx.conf:ro
      - ./certs:/etc/nginx/certs:ro
    restart: unless-stopped

volumes:
  postgres_data:
    driver: local

networks:
  default:
    driver: bridge

4. Production Nginx Configuration (nginx/nginx.conf)

events {
    worker_connections 1024;
}

http {
    include       /etc/nginx/mime.types;
    default_type  application/octet-stream;

    # Performance
    sendfile        on;
    tcp_nopush     on;
    tcp_nodelay    on;
    keepalive_timeout 65;
    client_max_body_size 50M;

    # Gzip Asset Compression
    gzip on;
    gzip_vary on;
    gzip_proxied any;
    gzip_comp_level 6;
    gzip_types
        text/plain
        text/css
        text/xml
        application/json
        application/javascript
        application/xml+rss
        image/svg+xml;

    # WebSocket Upgrade Mapping
    map $http_upgrade $connection_upgrade {
        default upgrade;
        ''      close;
    }

    # Upstream container definition (matches service name in docker-compose)
    upstream app_backend {
        server app-backend:5173;
        keepalive 32;
    }

    server {
        listen 80;
        server_name _;

        # Client header forwarding
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # WebSocket & HTTP/1.1 persistence
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;

        # Timeouts
        proxy_connect_timeout 60s;
        proxy_read_timeout 120s;
        proxy_send_timeout 120s;

        # Reverse Proxy Routing
        location / {
            proxy_pass http://app_backend;
        }
    }
}

5. URL Routing & Path Mapping Recipes

Recipe A: Single-Page Application (SPA / React / Vite / Next.js)

location / {
    proxy_pass http://app_backend;
}

Recipe B: Frontend on Root + API on /api/

# Backend REST API
location /api/ {
    proxy_pass http://api_backend;
}

# Frontend User Interface
location / {
    proxy_pass http://frontend_backend;
}

Recipe C: The Trailing Slash Rule

PATH STRIPPING VS. PRESERVING
  • No trailing slash (proxy_pass http://crawler;): Preserves the full URL. Client /crawler/run → Backend /crawler/run.
  • With trailing slash (proxy_pass http://crawler/;): Strips the prefix. Client /crawler/run → Backend /run.

6. Cloud Deployment & AWS Application Load Balancer (ALB)

When running on AWS EC2 behind an ALB, binding host ports below 1024 requires root privileges. Using Port 8443 Target Group solves this cleanly without sudo/root modifications:

  • ALB Listener: Port 443 (HTTPS) with AWS ACM Certificate.
  • ALB Target Group: Forwards to EC2 Host on Port 8443 (Health Check: /api/health).
  • Nginx Port Mapping: "${HTTPS_PORT:-8443}:443".

7. Production Troubleshooting & Diagnostic Matrix

Symptom / Error Root Cause Actionable Solution
502 Bad Gateway Upstream container is down, wrong container name, or port mismatch. Run docker ps to confirm container status and verify upstream host matches service name.
405 Method Not Allowed Testing with curl -I sends HTTP HEAD. Python/FastAPI endpoints only accept GET by default. Use curl -i (lowercase) to send GET with headers. Browsers always send GET.
Database Host Lookup Failure Special characters like @ in password break URL parsing (e.g. pwd@123@db). URL-encode password (@ becomes %40) in database connection logic.

8. New Project Implementation Checklist

  • [ ] 1. Identify internal application port (Vite: 5173, Next.js: 3000, FastAPI: 8000, Flask: 5000).
  • [ ] 2. In docker-compose.yml, place app under services: using 'expose: ["<PORT>"]'.
  • [ ] 3. In docker-compose.yml, configure nginx service with 'ports: ["${HTTP_PORT:-80}:80"]'.
  • [ ] 4. Mount nginx configuration as read-only: './nginx/nginx.conf:/etc/nginx/nginx.conf:ro'.
  • [ ] 5. In nginx.conf, set 'upstream app_backend { server <service_name>:<port>; keepalive 32; }'.
  • [ ] 6. Ensure WebSocket upgrade map block is included for modern hot-reloading and sockets.
  • [ ] 7. Launch stack: 'docker compose up --build -d' and verify: 'docker ps'.
  • [ ] 8. Verify endpoints: 'curl -i http://localhost' (HTTP 200 OK).
